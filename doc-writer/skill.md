# 开发项目文档写作（需求 / 用例 / 设计）

本 skill 在软件开发项目中产出三类核心文档：需求文档、用例文档、设计文档。覆盖 PRD、用例规格、概要/详细设计、技术方案、接口与数据模型。

> 注：本目录在 Windows 下实际文件名为 `skill.md`（与 `SKILL.md` 大小写不敏感等价），CodeBuddy 可正常识别。

## 写作纪律（硬性）

### 需求文档
- 每条功能需求带**唯一编号 + 验收标准**，验收标准用「给定…当…则…」可验证表述。
- 明确**范围边界**：区分 In Scope / Out of Scope。
- 非功能需求（性能 / 安全 / 兼容性）单列。
- 标注优先级（MoSCoW 或 P0/P1/P2）。

### 用例文档
- 以**参与者目标**驱动，而非功能罗列。
- 每个用例覆盖：基本流 + 扩展/替代流 + 异常流 + 前置/后置条件。
- 步骤用动词开头，可测试。

### 设计文档
- **先概要后详细**：先架构/模块划分，再接口/数据结构/关键流程。
- 接口须给出**契约**：方法、入参、出参、错误码。
- 用图（用例图 / 时序图 / ER 图）辅助，每张图配文字说明。
- 区分「已定」与「待确认」，开放问题单列。

## 写作流程

1. **定类型**：确认写需求 / 用例 / 设计哪一种，选对应模板。
2. **收输入**：需求来源、现有代码或系统、技术约束、干系人。
3. **套模板**：从本目录 `templates/` 取对应骨架（requirements-template / usecase-template / design-template），结构化填充，不跳节。
4. **自检**：
   - 需求是否每条有验收标准与编号？
   - 用例是否覆盖主/替/异？
   - 设计是否先架构后细节、接口有契约？
5. **出稿**：补全编号与图表说明。

## 模板

- `templates/requirements-template.md` — 需求文档骨架
- `templates/usecase-template.md` — 用例文档骨架
- `templates/design-template.md` — 设计文档骨架

## 注意事项

- 面向研发交付物，与「调研 / 结论文档」写法不同，勿混淆。
- 编号体系（FR-/UC-/模块名）项目内统一，新增时递增。
