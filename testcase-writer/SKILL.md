# 测试用例文档写作（测试计划 / 测试用例 / 清单）

本 skill 在软件开发项目中产出可执行的测试文档，覆盖测试计划、测试用例规格、冒烟/回归清单、测试报告。

> 注：因 Windows 大小写不敏感，`skill.md` 与 `SKILL.md` 视为同一文件，本 skill 以 `SKILL.md` 单一文件同时承载 frontmatter 与写作纪律。

## 文档类型

| 文档类型 | 常见名称 | 目的 |
|----------|----------|------|
| **测试计划** | Test Plan | 范围、策略、环境、入口/出口准则、进度 |
| **测试用例** | Test Case | 单条可执行的验证步骤与预期结果 |
| **测试清单** | Checklist | 冒烟 / 回归快速核验项 |
| **测试报告** | Test Report | 执行结果、覆盖率、遗留风险 |

## 写作纪律（硬性）

### 测试用例（单条）
- **唯一编号** `TC-xxx` + 稳定标题，不重排。
- **前置条件**清晰：环境、数据、初始状态。
- **步骤**编号、可执行、无歧义，含具体测试数据。
- **预期结果**可验证，与需求验收标准对齐（避免「系统正常」这类不可验证描述）。
- **可追溯**：每条用例关联需求/用例编号（`FR-` / `UC-`）。
- **覆盖类型**：正向、负向、边界（缺一不可）。
- 标注**优先级**（P0/P1/P2）与**类型**（功能 / 集成 / 回归 / 性能 / 安全）。

### 测试计划
- 范围边界（In / Out Scope）、测试策略、环境与数据。
- 入口 / 出口准则（如「所有 P0 用例通过」）。
- 用例与需求覆盖率可追溯（可追溯矩阵）。

### 测试报告
- 执行结果（通过/失败/阻塞）、覆盖率、缺陷汇总、遗留风险。

## 写作流程

1. **定类型**：测试计划 / 测试用例 / 清单 / 报告。
2. **收输入**：需求文档（`FR-`）、用例文档（`UC-`）、接口/代码。
3. **套模板**：从本目录 `templates/` 取 `testcase-template.md` 填充，不跳节。
4. **自检**：
   - 每条用例是否能独立执行？有无预期结果？
   - 是否关联需求/用例编号？
   - 是否同时覆盖正向、负向、边界？
5. **出稿**：补全编号、追溯矩阵与状态。

## 模板

- `templates/testcase-template.md` — 测试计划 + 可追溯矩阵 + 测试用例骨架

## 注意事项

- 编号体系（`FR-` / `UC-` / `TC-`）与需求、用例文档保持一致，保证端到端可追溯。
- 用例面向「验证需求是否达成」，而非罗列功能点；负向与边界用例是质量关键。
