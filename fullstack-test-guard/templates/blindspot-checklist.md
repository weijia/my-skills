# 测试盲区自查清单（交付前逐项打勾）

> 「测试全绿」不等于「没问题」。逐项确认，任一项未打勾都必须在测试计划里写明为遗留风险。

## 一、画出现有测试的层次与盲区

- [ ] L1 组件渲染：是否 mock 了 api 模块？→ 盲区：不验证接口是否真实存在
- [ ] L2 交互 E2E：是否**全量离线桩**？→ 盲区：后端 500/404 被完全掩盖
- [ ] L3 接口测试：是否 `drop_all + create_all` 建新库？→ 盲区：生产缺表测不出
- [ ] L4 生产一致性：有没有任何一层会碰到**真实数据库**？（通常没有）

## 二、契约守卫（抓 404 / 路径漂移）

- [ ] 已自动比对「前端调用的 API 路径」与「后端路由表」
- [ ] 该检查接入 CI，不匹配即失败
- [ ] 存量漂移已修掉（常见：后端重构后前端/测试仍用旧路径）

## 三、Schema 守卫（抓缺表 / 缺列）

- [ ] 有脚本比对 ORM 元数据与目标库 schema
- [ ] 支持通过 `DATABASE_URL` 指向生产库做一次性校验
- [ ] 已知 `create_all` **只建表不补列**，已存在表的列变更需显式 ALTER

## 四、部署守卫

- [ ] 迁移 Job **每次发布都会重跑**（同名 Job 需先 delete 再 apply）
- [ ] 迁移 Job 的镜像 = **本次发布的 SHA**（非固定 tag）
- [ ] 迁移**等待完成**，失败即中断发布
- [ ] 健康检查不止打 `/health` 与 `/version`，包含业务端点
- [ ] 业务冒烟含「401/200 之外即失败」的断言（500 是缺表探针）

## 五、断言质量

- [ ] 断言覆盖 HTTP 状态码 / 业务 code，而非只断言"文字可见"
- [ ] 每个页面/接口有负向用例：接口失败时不白屏、有可见反馈
- [ ] 存在**至少一组打真实后端**的用例（可 skip，但必须存在且有清单）

## 六、遗留风险登记

- [ ] 测试计划文档写明「尚未覆盖」清单（如行内编辑/删除、表单落库、分页排序）
- [ ] 明确区分「已覆盖」与「已通过」，避免全绿被误读为全覆盖

## 附：排查「线上报错但测试全绿」的标准动作

1. 复现：区分「SPA 外壳 200 + 接口 5xx」还是整页 5xx
2. 打 `/version` 拿 `git_commit`，确认线上跑哪次提交
3. `git merge-base --is-ancestor <引入提交> HEAD`
   - 否 ⇒ 部署问题（代码没上去）
   - 是 ⇒ 运行时/环境问题（缺表、缺配置、缺数据）
4. 沿上面的四层表定位盲区
5. **补上那一层的守卫**，而不是只修这一个 bug
