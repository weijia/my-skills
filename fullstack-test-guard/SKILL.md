# 全栈测试盲区守卫

> 起因：某项目「所有页面 + 所有按钮」共 111 个 E2E 用例全绿、组件单测全绿，
> 但线上打开 `/iot/group` 直接 500。原因是生产库缺表（迁移 Job 从未重跑），
> 而**没有任何一层测试会碰到真实数据库**。全绿 ≠ 没问题。

## 核心原则

**测试全绿只能证明「被 mock 覆盖到的那部分」是对的。**
每引入一层 mock，就同时引入一层盲区。必须显式登记并补偿这些盲区。

## 四层测试与各自盲区（必须先画出这张表）

| 层 | 典型手段 | 验证什么 | **必然的盲区（必须补偿）** |
|---|---|---|---|
| L1 组件渲染 | vitest + @vue/test-utils，mock api 模块 | 给定数据能渲染 | 数据从哪来、接口是否存在，一概不验证 |
| L2 交互 E2E | Playwright + **离线桩**（`page.route` 全量 mock） | 按钮能点、弹窗能开 | **后端 500/404 被完全掩盖**；页面"能渲染"是桩给的 |
| L3 接口测试 | pytest + sqlite，`drop_all`+`create_all` 建新库 | 业务逻辑正确 | **表永远存在** → 永远测不出生产缺表/迁移缺失 |
| L4 生产一致性 | 通常没有 | — | **500 类问题的藏身之处** |

**关键**：L2 与 L3 是最容易让人误判的两层。
- L2 全 mock ⇒ 后端挂了测试照样绿。
- L3 自动建表 ⇒ 生产缺表测试照样绿。

## 硬性纪律

### D1：禁止 100% 离线桩，必须保留真实后端用例
离线桩用例之外，必须有**至少一组**打真实后端的用例（可 `test.describe.skip` 标记需环境，
但要存在、要有清单、要在环境就绪时启用）。否则后端任何故障都无法被测出。

### D2：契约守卫（抓 404 / 路径漂移）
自动比对**前端调用的所有 API 路径**与**后端真实路由表**，未匹配即失败。
> 手工发现过的真实漂移：`/system/config/list` → `/config/list`、
> `/account-open/supply-partner/list` → `/account/supply-partner/list`。
> 这类漂移靠人肉排查，必须改成自动比对。

### D3：Schema 守卫（抓缺表 / 缺列）
比对 ORM 元数据（`Base.metadata.tables`）与**目标数据库真实 schema**，报告缺失的表与列。
必须支持通过环境变量指向生产库作为一次性校验。
> `create_all` 只在表不存在时创建，**不会补列**；且迁移脚本若只在首次部署跑过，
> 后续新增的模型永远不会有表。

### D4：部署期迁移守卫（抓"迁移 Job 没重跑"）
- Kubernetes **同名 Job 再次 `kubectl apply` 不会重新执行**——必须先 `delete` 再 `apply`。
- 迁移 Job 的镜像必须**与本次发布的镜像同 SHA**，不能用固定 tag（如 `:1.0.0`）配
  `imagePullPolicy: IfNotPresent`，否则会用陈旧镜像建表。
- 迁移必须**等待完成**（`kubectl wait --for=condition=complete`），失败即中断发布。
- 健康检查不能只打 `/health`、`/version`——那只能证明进程活着。

### D5：断言要验状态码，不能只验"渲染成功"
- 反面：`await expect(page.getByText('XXX')).toBeVisible()`（数据来自桩，永远通过）
- 正面：断言 HTTP 状态、业务 `code`、以及**错误态的可见反馈**。
- 每个页面至少有一条"接口失败时页面不白屏"的负向用例。

### D6：显式登记未覆盖范围
测试计划必须写明"尚未覆盖"清单（如行内编辑/删除、表单提交落库、分页排序），
避免"全绿"被误读为"全覆盖"。

## 执行流程

1. **画盲区表**：列出项目现有测试处于哪几层，逐层写出"它不可能发现什么"。
2. **补契约守卫**（D2）：跑一遍，先修掉存量路径漂移。
3. **补 Schema 守卫**（D3）：对目标库跑一遍，报告缺失表/列。
4. **补部署守卫**（D4）：修迁移 Job 重跑逻辑 + 镜像 SHA + 等待完成。
5. **补真实后端冒烟**（D1）：至少覆盖各模块的 P0 列表接口 + 关键页面。
6. **更新测试计划文档**，写入"尚未覆盖"清单（D6）。
7. **回归**：全套件跑绿后提交。

## 排查「测试全绿但线上报错」的标准动作

1. 复现：直接 curl 线上页面与接口，区分是 **SPA 外壳 200 + 接口 5xx** 还是整页 5xx。
2. 确认线上版本：打 `/version` 拿 `git_commit`，确认线上跑的是哪次提交。
3. 确认代码是否已含该功能：`git merge-base --is-ancestor <引入提交> HEAD`。
   - 不含 ⇒ 部署问题（代码没上去）
   - 含 ⇒ 运行时/环境问题（缺表、缺配置、缺数据）
4. 追问"为什么测试没碰到"：沿上面的四层表定位盲区，然后补对应守卫。
5. **不要止于修这一个 bug**，必须补上那一层的守卫，否则同类问题会反复出现。
